# Risk register — likely defects found by inspection, one line each

Each line is the prompt for a dedicated verification. A line stays here until it
is either **cleared by evidence** or **confirmed and fixed**. Cleared lines are
kept (not deleted) so the same suspicion is not re-investigated from scratch.

## Cleared by evidence

- **(XB) Coach/evaluation endpoints skip the account-status check.** Cleared
  2026-09-26: with a session cookie belonging to a SUSPENDED student,
  `POST /api/writing/submissions/:id/submit`,
  `POST /api/grammar/exercises/:id/produce`, `POST /api/grammar/exercises/:id/practice`,
  `POST /api/vocabulary/:id/use` and `POST /api/assignments/:id/evaluate` all
  answered **401**. Every one of them resolves the caller with `requireActiveUser`.
  Reproduce: suspend `demo.student@learnersarea.uz` in the database, keep the old
  cookie, call each route, restore the account.
- **(XE) Reading attempts missing an active-user guard.** Cleared
  2026-09-26: `POST /api/reading/attempts` and
  `POST /api/reading/attempts/:id/submit` answered **401** for the same suspended
  session, while the student's own page redirected to `/login`.
- **(XJ) Vocabulary search has a weak authorization check.** Cleared
  2026-09-26: `GET /api/vocabulary/search` answered **401** for the suspended
  session (and 200 before the suspension), so it is behind the same active-user
  guard plus its own rate limit.

## Confirmed and fixed

- **(XC) Admission review could approve the same request twice.** Confirmed
  2026-09-26 by firing two approvals in parallel: the read-then-write sequence let
  both callers pass the "still pending?" check, producing two status writes, two
  notifications and two audit entries. Fixed in `src/lib/data/admission.ts` by
  claiming the decision with a conditional update
  (`where id = … and status = 'pending' … returning id`); the loser now gets
  `already_decided`. Regression test: `scripts/verify-admission-race.mjs`
  (6 checks: one 200 and one 409, one status row, one audit row, one notification,
  the account becomes ACTIVE, and a later attempt gets 409).
