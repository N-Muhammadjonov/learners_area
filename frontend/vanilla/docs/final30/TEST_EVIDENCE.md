Test files: slice1-people (18), slice2-owner (14), slice3-teacher (10), slice4-live (7), slice5-grammar (10), slice6-reading (6), slice7-writing (11), slice8-upload-composer (12), slice9-materials (3), slice10-video (6), slice11-retention (13), slice12-workspace (7), slice13-reading-import (8), slice14-speaking (15), slice15-listening (10), slice16-dictionary-panel (7), slice17-listening-legacy (11), routes (3).
First-run failures occurred in most slices. Almost all were test-side mistakes (wrong expected arithmetic/selector, fixtures that violated the source's own min-length rules, a missing jsdom `<dialog>` polyfill). Two were real module defects found by the tests and fixed: (1) a per-render closure used as the double-submit guard let a second submit through after a re-render (video lessons; guard moved into persisted state); (2) the upload engine sent the discard DELETE twice on cancel (now once); (3) the retention editor used `AbortSignal.any` for DOM listeners (works in browsers; jsdom rejects cross-realm signals) — listeners now take the page signal, requests the combined one. One more real defect was found late and fixed everywhere: native `Element.append()` stringifies `null` and arrays, so several forms rendered stray "null" / "[object HTMLFieldSetElement]" text (61 call sites now use a null/array-safe `put()`); a regression test asserts no form renders those strings. `replaceChildren` had the same null/array problem (19 sites, now `setChildren`), and a double-submit race in the listening import (the busy flag was set only after an await) was fixed with a synchronous flight guard. The harness now carries a global tripwire: every test's `dispose()` fails if the rendered page text contains `null`, `undefined` or `[object …]`. No assertion was weakened to pass.
