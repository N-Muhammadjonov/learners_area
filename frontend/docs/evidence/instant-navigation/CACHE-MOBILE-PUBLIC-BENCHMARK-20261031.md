# Learners Area — cache / prefetch / mobile / external benchmark

## Scope

Frontend-only optimization, with no API contract, backend session, SSE or SQL changes.

- **Data cache:** retains the existing identity-scoped `privateScope` and `cache-policy.js` allowlist. Active attempts, writing submissions, live-class rooms, vocabulary SRS/revision queues and notifications are not added to cached views.
- **Intent prefetch:** bounds private reads to one outstanding warm-up, a 1 MiB per-workspace budget, and a six-target/minute policy; limits response bytes and cancels optional prewarm when workspace aborts. Prefetch is never an authorization grant.
- **Mobile:** turns off optional idle private-data prewarm on coarse-pointer/width <768px and low-resource devices, while keeping explicit navigation and permitted user intent. This removes network contention as an *attempt to reduce* mobile ready-tail latency. It does **not** establish a new p99 result.
- **Booster:** `frontend/vanilla/scripts/public-cold-start-compare.mjs` measures both publicly accessible page loads in a fresh, isolated Chromium context using alternating order. It must not be reported as equivalent authenticated SPA navigation; page complexity, authentication, server/network conditions, and caching vary.
- **Cold starts:** the same script records response start, DOMContentLoaded, FCP and LCP when available. Authenticated navigation remains covered separately by `instant-navigation-bench.mjs`.

## Commands

```sh
npm ci
cd frontend/vanilla
node --test tests/view-prewarm-budget.test.mjs
node scripts/public-cold-start-compare.mjs --ours https://learnersarea.uz/login --other https://ieltsbooster.uz/ --cycles 5
```

For full navigation/regression on the same build: `npm test`, `npm run build`, then preview and `instant-navigation-bench.mjs` with `--viewport mobile`, `--api-delay 250` and `--mode security`.

## Release criteria

1. Full frontend suite and real mobile Chromium run without failures.
2. No extra `/api/auth/state` requests on warm navigation; SSE/session revocation unchanged.
3. Cache identity/role/logout invalidation still clears all private state.
4. Mobile p99 compared on the **same build, device, data fixture, benchmark method**, before and after.
5. Public Booster benchmark must succeed for both sites and show samples with exact page URLs. Do not call the sites equally fast or better until measured.
6. Production TTFB/LCP/INP require a reachable deployment and field metrics. No production metrics have been generated by this code change alone.

## Status

Changes committed for development integration. **Mobile p99 improvement, Booster speed equality, and real production cold-start improvement are not yet empirically verified.** These are measurement tasks and cannot be concluded from static source inspection.
