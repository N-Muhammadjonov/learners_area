# V5 Phase 1 source-state closure audit

## Gate and limits

**Phase 1 ordinary FRONTEND CODE COMPLETE / FIXTURE VERIFIED. Overall migration PARTIAL.** This closes native clients, not unavailable server adapters, visual comparison, live integration or production acceptance. No Phase 2 implementation has been started in V5. The following nine canonical source routes are the bounded Phase 1 denominator: `/`, `/login`, `/register`, `/auth/recovery`, `/reset-password`, `/reset-password/confirm`, `/onboarding`, `/pending`, `/app/profile`. Desktop intro is a state of `/`, NOT an invented `/intro` page. Telegram confirmation/exchange is a login/profile state, NOT an invented account-confirmation route. Provider callbacks remain existing server handlers.

`evidence/v5/phase1-source-audit.json` records SHA256 of all nine original page files and 51 relevant original component files, native counterparts, source-state groups and executable proof locations. This is an engineering review record, not an automatic proof of visual identity. Original files were read-only. V4's recovery/reset/Breadcrumbs/ModuleContextHeading/GlobalSearch closures are preserved.

## Proof and defects actually repaired

211 complete unit tests (30 above V4's181) and202 Chromium cases (27 original +14V2 +49V3 +72V4 +40V5), zero failed/skipped in final validation. Tests are transport fixtures, never production APIs. V5's12 profile/name/photo journeys and12 onboarding journeys cover390×844/768×1024/1440×900 × EN/UZ × day/night, plus adversarial Telegram, pending, authority, diagnostics, private loader, dialog races, locale/mutation/focus/scroll and late photo cancellation cases. Historical cases remain intact; `scripts/regression-v5.mjs` snapshots/restores old evidence while storing separate new output.

Important reproduced defects fixed rather than called integration blockers: wrong-realm multipart AbortSignal; browser CSP blob decoding; premature malformed ACK success; stale confirm-select close event; AuthShell misclassified as private diagnostics; late diagnostic frames/outcomes; source private header stale mutation-state reference; preference invalidation destroying unchanged-identity shell; locale scroll/keyboard focus/caret loss; asynchronous route without h1 focus fallback; and ordinary sidebar replacement on each navigation. The latter caused an immediate post-GC +78-listener delta; stable nav synchronization removes that growth in the measured30-switch trace. The earlier report is retained as `navigation-performance-immediate.json`, NOT current performance. No general leak-freedom guarantee.

## Deliberate boundaries / deviations

- No claim that source-compatible markup/CSS/assets equals original-rendered comparison. Screenshots are candidate-only. Safari/real microphone/device/live acceptance are absent.
- Native controllers replace framework context/hooks; no React/Next runtime, virtual DOM or hidden server rendering. Codewarming never prefetches private DTO/media/answers.
- Support module metadata uses actual module/profile, correcting the source first-segment `app` fallback, rather than regressing the existing native behavior.
- Strict ACK checks, safe category/error/opaque-hint validation and reliable cancellation are defensive native adaptations, not new server authority.
- Ten off-Phase1 component files remain partial, including ModuleNavigation/ModuleSectionNav composition. Vocabulary's native module-layout branch is still missing and belongs to Phase7; it is not a shell closure. Broader BrandLogo API and unused standalone FocusToggle/TestFocusEntry are not counted complete through superficially similar shell UI.
- Remaining frontend:19 canonical partial +80 notstarted,10 component partial +145 notstarted. Missing engines/staff workflows are ordinary frontend work, not external blockers. Follow Phase2–10 in the required order.
