# Section Entry Reliability

## Scope and evidence

This audit is limited to private-section entry, internal navigation/loading, query fan-out, and failure boundaries for Dashboard, Live Classes, Assignments, Listening, Video/TED, Reading, Writing, Speaking, Grammar, Vocabulary, Progress, and Mocks. It does not introduce a shared cache/SWR platform, a general BFF migration, prefetch redesign, data migration, or product redesign.

The Vocabulary server digest `2524476368` was not reproduced or mapped to a specific query/stack trace. The changes below remove the page-level database fan-out and isolate expected data-query failures, but **do not establish that this digest was the confirmed production root cause**. Authenticated Preview/browser acceptance for the final SHA is **EXTERNALLY UNVERIFIED**.

## Shared private-route entry behavior

- The `(app)` layout still calls `getCurrentUser()` and checks `hasPrivateAccess()` before rendering the private shell. Section pages and private APIs retain their server-side active-user gates; protected reads remain scoped by user/owner ids.
- Ordinary same-origin internal navigation uses the existing Next App Router. The interaction provider records a stable, privacy-safe destination key, immediately renders a localized `SectionEntryFrame`, and leaves the sidebar, topbar, active/pending navigation, main scroll container, and browser history under the existing shell/Next router. It does not write browser history directly.
- Cold loads, direct URLs, refreshes, and pending route commits use the synchronous, route-aware `(app)/loading.tsx` fallback. It does no auth or database work; the server layout remains authoritative. After route commit, section-local `Suspense` fallbacks identify the specific unresolved data region.
- Back/Forward scroll restoration, direct URL/refresh handling, stable nested-route frame keys, shell retention, and click acknowledgement are covered structurally in `tests/section-entry-loading.test.ts` and `tests/section-navigation-regression.test.ts`. These are not substitutes for browser acceptance.
- `RegionFailureNotice` retries the current App Router route with `router.refresh()` rather than reloading the document. The Vocabulary client/API regions have narrower fetch retries. For server-rendered regions, a route refresh can re-run sibling server reads; it preserves the shell, but is not a promise that only one SQL statement will be repeated.

## Vocabulary failure-state coverage

`tests/ui/vocabulary-entry-failure.test.tsx` covers empty library/zero folders, normal words with nullable lexical fields and present folders, many words with page-bounded rendering, zero/present sentence history including nullable historical evaluation ids, empty standing, legacy award display, and local retry for library/summary/folders/sentence-history/standing/awards. `tests/vocabulary-entry-failure.test.ts` and the engine/DB contract suites cover server auth, 503/no-store behavior, safe nullability, grouped zero/all-source aggregates, and effective legacy ledger calculations. Database-backed tests are conditional on their configured test database; their status is reported separately from always-on unit/structural tests.
