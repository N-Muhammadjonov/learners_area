### Reporter teacher-roster historical-window regression

- **Defect found:** teacher activity metrics used the current `teacher_student_links` rows without a report-window cutoff. A link created after a historical report's end could therefore reveal the learner's earlier activity. The separate `people.assigned` metric already used the exclusive window end, so scope behavior was inconsistent.
- **Fix:** `src/lib/reporter/snapshot.ts` now applies `l.created_at < :to` in the teacher `ROSTER` predicate used by learner metrics. `:to` is the canonical report window's exclusive end; assignment after that instant cannot retroactively disclose activity. Owner/admin cohort predicates and current request authorization are unchanged.
- **Regression:** `tests/reporter.test.ts` RP14 now exercises an assignment before the window, an assignment inside the window, and a second assignment one millisecond after the exclusive end. It verifies only the in/before-window learner contributes, the post-window learner's historical activity is excluded, provenance retains the exact period end, and owner/admin scope counts remain unchanged. RP15 continues to assert unassigned/missing targets are indistinguishable 404; no IDOR widening was added.
- **Verification:** targeted Reporter suite passed 18/18 in PGlite and 18/18 against isolated real PostgreSQL. The exact RP14 regression passed in both final full gates' real-PostgreSQL runs and in the final integrated red team. The pre-fix focused run reproduced the bug (`3 !== 1`), establishing the test is not vacuous.
